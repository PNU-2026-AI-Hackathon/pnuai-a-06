# AI 도구 활용 내역

## 1. 활용한 AI 도구

- **OpenAI Codex**를 저장소 탐색, 코드 작성·수정, 테스트, 오류 분석 및 문서화를 지원하는 AI 개발 보조 도구로 활용하였다.
- 개발 과정에서 사용한 AI 코딩 도구는 Codex가 유일하다. 서비스 요구사항, API 정책, 데이터 구조와 최종 코드 채택 여부는 팀원이 직접 결정하였다.

## 2. 활용 범위

Codex에 기능 요구사항과 기존 코드의 제약조건을 설명하고, 저장소 전체의 연관 코드를 먼저 분석하게 한 뒤 구현 초안을 생성하는 방식으로 활용하였다. 주요 활용 범위는 다음과 같다.

- **백엔드 구조 및 API 개발**: FastAPI의 Router–Service–Schema–Model 계층을 유지하면서 회원 인증, 일정·초대, 일정별 미션 관리 API를 구현·보완하였다. 기존 API 변경을 최소화하고 HTTP 상태 코드와 오류 코드를 프론트엔드 계약에 맞추는 데 활용하였다.
- **미션 수행 로직**: `WAITING`부터 `COMPLETED`·`CANCELLED`까지 이어지는 미션 세션 상태, 참가 여부, 사진 제출, 댓글·좋아요와 투표 흐름을 구현하였다. 방장 취소 시 DB 상태 변경, 활성 세션 제외, 전체 참가자 WebSocket 이벤트 전파처럼 여러 기기의 상태가 일치하도록 관련 코드를 함께 점검하였다.
- **GPS 검증 및 관리 기능**: 위도·경도, 측정 시각, 기기 정확도와 허용 반경을 검증하고 여러 허용 지점 중 하나에 포함되는지 계산하는 로직을 작성하였다. 미션별 위치와 개발자 테스트 위치를 관리하는 별도 관리자 화면 및 DB 구조도 보조하였다.
- **데이터베이스 및 다국어 처리**: SQLAlchemy 모델, 트랜잭션 및 Alembic 마이그레이션을 작성하고 기존 데이터가 유지되도록 변경 순서를 설계하였다. 한국어를 기본값으로 유지하면서 미션·장소·상세 주소의 영어 번역과 필드별 fallback을 적용하였다.
- **AI·미디어 기능 연동**: 미션별 판정 기준과 제출 사진을 이용하는 비동기 이미지 판정, 특정 일자의 방문 순서 추천, 완료된 미션 사진·설명·댓글을 합성하는 매거진 생성 기능의 서버 코드를 구현·수정하였다. 이미지 파일은 로컬 저장소에서 관리하되 향후 S3로 교체할 수 있도록 URL 중심의 응답 계약을 유지하였다.
- **인증·성능·운영 개선**: 이메일 인증과 비밀번호 재설정, 카카오 계정 연결 해제 및 회원 탈퇴, 접근 권한 검사를 보완하였다. DB 커넥션 풀 설정, WebSocket의 장시간 DB 세션 점유 해소, 요청 시간 로깅과 URL의 인증 토큰 마스킹 등 성능·보안 관련 문제도 로그를 바탕으로 개선하였다.
- **프론트엔드 화면 및 구조 개발**: Expo Router와 React Native를 기반으로 인증, 홈, 지도, 미션, 일정 생성·초대·수정, 미션 촬영·판정·투표, 매거진 화면을 구현·보완하였다. 화면에 집중되어 있던 로직을 기능별 컴포넌트·Hook·스타일·API 모듈로 분리하고, 상단 바·하단 내비게이션·미션 카드처럼 반복되는 UI를 공통 컴포넌트로 정리하는 데 활용하였다.
- **API 및 기기 기능 연동**: FastAPI 응답 계약에 맞춰 access token 자동 갱신, 일정·초대·미션 세션 API, WebSocket과 polling fallback을 연결하였다. Expo Camera·Location 권한과 촬영·GPS 제출 흐름, 카카오 로그인·공유·딥링크를 Android와 웹의 실행 환경 차이를 고려해 구현하고 예외 상황을 보완하였다.
- **프론트엔드 UX 및 상태 안정화**: 한국어·영어 전환, 화면별 최초 1회 튜토리얼, 반응형 레이아웃과 로딩·빈 상태·실패 상태를 구성하였다. 빠른 중복 입력 방지, 화면 이탈 시 timer·socket 정리, 세션 만료 및 취소 처리, 매거진 이미지 캐시처럼 비동기 상태에서 발생하는 경합과 불필요한 재요청을 줄이는 데 활용하였다.
- **테스트와 문서화**: 기능별 회귀 테스트, OpenAPI 명세, README와 프론트엔드 연동 안내, 서버 실행·DB 복구 절차를 실제 코드와 일치하도록 작성하는 데 활용하였다.

## 3. AI 생성 코드의 검증·수정 방식

AI가 제안한 코드는 그대로 병합하지 않고 다음 절차로 검증·수정하였다.

1. **요구사항 대조 및 코드 리뷰**: 팀원이 기능의 정상·예외 흐름을 먼저 확정하고 `git diff`로 변경 범위, 기존 API 호환성, 계층 구조, 중복 코드와 비밀정보 포함 여부를 검토하였다. 프론트엔드는 화면 전환, API 오류 분기, 비동기 상태 해제와 기기 권한 처리도 함께 확인하였다. 범위를 벗어난 제안은 제거하고 프로젝트 명명 규칙과 도메인 정책에 맞게 직접 보정하였다.
2. **자동화 검증**: 백엔드는 `conda`의 `pnuai` 환경에서 관련 `pytest` 회귀 테스트를 실행하고 Python 문법과 OpenAPI 스키마 생성을 확인하였다. 프론트엔드는 `npm run lint`와 TypeScript 정적 검사를 사용해 Hook 의존성, 잘못된 import와 타입 불일치를 점검하였다. 공통으로 `git diff --check`를 수행해 형식 문제를 확인하였다.
3. **DB 검증**: Alembic revision의 연결 관계와 upgrade 동작을 PostgreSQL에서 확인하였다. 제약조건, sequence, 기존 행의 보존 여부와 조회 정렬 결과를 실제 DB 쿼리 및 API 응답으로 검증하였다.
4. **통합·실행 검증**: 인증과 권한별 API 응답, GPS 경계값, WebSocket 연결·해제 및 취소 이벤트, 이미지 생성 결과를 직접 재현하였다. 프론트엔드는 Expo 개발 빌드와 웹에서 로그인·딥링크, 일정 편집, 카메라·위치 권한, 미션 수행부터 결과 확인까지의 흐름을 점검하였다. 서버와 앱의 로그를 함께 확인하고 실패 원인에 따라 쿼리, 트랜잭션 또는 비동기 상태 처리를 반복 수정하였다.
5. **보안 및 운영 검토**: JWT·관리자 키·API 키와 프론트엔드 환경변수가 응답이나 Git에 포함되지 않는지, 로그의 토큰이 마스킹되는지 확인하였다. 변경 사항은 기능 단위로 나누어 커밋하기 전에 테스트 결과와 수정 파일을 다시 확인하였다.

이처럼 Codex는 코드 탐색과 반복 구현의 시간을 줄이는 보조 수단으로 사용하였으며, 생성 코드의 적용 여부와 서비스 규칙, 정확성·보안·운영 품질 및 사용자 경험에 대한 최종 책임은 팀원의 검토와 실행 검증을 통해 관리하였다.
